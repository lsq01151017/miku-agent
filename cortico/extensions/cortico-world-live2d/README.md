# cortico-world-live2d

Owner: `src/index.ts`

让 Live2D 形象由三件事共同驱动:**她的内部状态**(情绪与心情)、**她说的话**(词表命中与
措辞指令)、**这款模型自带的表情**,再用一个网页播放器渲染出来。素材来自 `vtuber-pack`
——一份数据包,不是代码。

| 文件 | 内容 |
|---|---|
| `src/pack.ts` | 读 `params.json` / `clips.json` / `vocab.json` / `expressions.json` / `pat.json`,并报出数据缺口 |
| `src/baseline.ts` | 内部状态 → 通道基线(情绪驱动的那一层) |
| `src/expressions.ts` | 心情 → 模型自带表情 |
| `src/directives.ts` | 台词 → 演出指令(措辞命中哪个表情) |
| `src/channels.ts` | 抽象通道 → 本模型参数的解析与核对 |
| `src/performance.ts` | 合成:基线 + 片段 + 时间线,按量程裁剪 |
| `src/voice.ts` | 回复流的语音分段器:句界切分段,攒短句、封长句 |
| `tests/` | 素材包读取、基线映射、词表触发、措辞指令、通道核对、表情层、World 的路由与推流、对话框代理、语音分段、合成入队与按序取件、页面的振幅口型与清队 |

## 五层

1. **基线**——情绪驱动,一直在。这是题目要求的「身体由内部状态驱动」:六个维度各自相对自己
   的出厂基线归一化,再映射到通道。口型不在其中,它归说话。
2. **待机动作**——呼吸、微晃、视线游移,按绝对时间算(几个不同周期的正弦),一直在。
   有了它,"她什么都没说"的时候也不是一张静止的图;幅度由 `idleAmount` 调,设 0 就完全静止。
3. **片段**——词汇表命中触发。三种形状:关键帧的 `pulse`(一次手势)、保持值的 `sustain`
   (表情/姿态)、视线目标 `gaze`。同分类的 state 互相替换,不同分类可以并存。
   说话本身也走这一层:每句起音一次 `speech_onset`,之后每说满 14 个字点一下头,
   重音片段按序轮换——同一句里不会连着两次同一个动作。轮换而不是随机:同一时刻同一输入
   必须算出同一组值。
4. **表情**——两种来源,后写的压前面的:离散心情挂这款模型自带的表情(脸红/前倾/圈圈/唱歌/比心
   里的四个),她的**台词**再按 `expressions.json` 的措辞表挂一张(见下节),保持 `expressionHoldMs`
   之后回到心情那张。这一层与通道写的是**不相交的参数组**:表情只写 `Param125` 与 `Param130-137`,
   所以同时生效、谁也不覆盖谁。表里没有的心情(寂寞、低落、认真、平静)不挂表情,交给连续的基线。
   葱、QQ人、水印不是情绪,不在心情表里;水印走下面的定值。
   表情挂上的那一刻播它的**伴随动作**(`staging` 段:一个片段,加一组通道值)——开关参数不改
   五官,通道值才是"看得出来"的那一半;通道值跟着表情的寿命走,换挡即换掉。
   开关参数由页面**每帧**先清零整组、再写当前那张的值:库的表情队列永不结束,挂过的表情会一直
   叠着(唱过歌再说「比心」会显示成唱歌),清一次修不掉,每帧清零才修得掉。
5. **合成**——相加后按 `params.json` 的量程裁剪。待机动作与扫视都是时间的纯函数,不是随机数:
   同一时刻同一输入算出同一组值。

## 页面上的数与取景

播放器页面(形象页)右侧是一块数值面板,数**全部来自推流帧**,页面不自己算:

| 显示 | 来自帧里的 |
|---|---|
| 六个情绪维度(条 + 两位小数) | `emotion` |
| 心情、此刻的表情 | `mood`、`expression` |
| 正在做的片段 | `clips` |
| 说话中、连着几页 | `speaking`、`clients` |
| 每个通道此刻的值 | `channels`(已经过通道偏移与量程裁剪) |

取景是给人用的:缩放、左右、上下三个滑块,外加直接用鼠标拖动画面,一个复位键,一个"记住"
把当前取景写进 `localStorage`。取景只影响画面,不回写模型、不进 World——她的表演数据与
画面怎么摆是两件事。

页面版本钉在入口里(`window.__DSH_PAGE_VER__`,取 `index.html` 与 `app.js` 的大小和修改时间),
每帧随 `/state` 下发;页面发现帧里的版本与自己的不符就自刷新——换过页面之后挂着的旧标签页
重连后自己换成新的,不必记得手动刷新。文件没动过的重启版本不变,连着的页面不会白刷。

面板、字幕、输入区与按键是同一套**白玻璃流行牌**(白底 + 2px 墨线 + 硬投影;悬停落青,
按压把投影按回去),颜色按角色锁死:青 = 交互与她的数据,钢蓝 = 标签,黄 = LIVE 徽标。
变量在 `web/index.html` 的 `:root` 里,要调质感只改那几行。

## 她的话是字幕,我发过的话在底部输入区

形象页底部一条扁输入区,上面浮着一条白底墨边的字幕——按操作员看到的东西分:

| 看到什么 | 从哪来 |
|---|---|
| 她的回答(字幕,一段一段替换) | `/state` 帧里的 `speaking` 决定起止;文本走下面两条路之一 |
| 我发过的话(收起时只显示最近一句,按「历史」展开) | 页面上发的,不回显成气泡 |
| 数值面板 | 同一份 `/state` 帧 |

**吩咐也能让她动**:操作员打的字原样交给本 World 的 `perform()`,它跟她的台词走同一条词表通道——
「张嘴」「点点头」这类吩咐直接触发对应片段,不必等她自己说出来。这条线由 Persona 递话
(`onOperatorText`),与情绪那条线并列;World 没实现就是空转。

口型因此有三层来源:语音在放时跟真实振幅(见下节);没语音时取「说话振荡」与「World 给的
通道值」里大的那个(片段驱动的「张嘴」走通道这一路),所以说话当中被要求张嘴也看得出来。

输入有两条路,配哪个走哪个:

- **控制台通道**:`worlds.live2d.consoleUrl`(例如 `http://127.0.0.1:18790`)。页面连本 World 的
  `/chat`,由 World 转到控制台的终端流式通道。转一手是因为"跟她说话"本来就是同一串消息:
  控制台的终端页看到的是同一份,两边可以交替说;页面则只需要知道自己的来源,不必知道控制台在
  哪个端口,也不用处理跨来源。
- **外部 Agent**:`worlds.live2d.agentUrl`(例如 `http://127.0.0.1:8790`)。输入 `POST` 本 World 的
  `/agent/chat`,World 再转给 `POST <agentUrl>/agent/chat`(JSON `{ message }`),把它流回来的文本
  一边当字幕推给页面,一边喂进表演层——**外部 Agent 说的同样是"她说的话"**:台词片段、措辞表情、
  口型与说话时长都按这段文本走,它不必知道 Live2D 的任何事情。
  回包宽容:SSE(每段 `data:` 里是 JSON 的 `delta`/`text`/`reply`/`message`/`content`、OpenAI 那层
  `choices[].delta.content`,或直接一段文本)可以,一次性 JSON 或纯文本也可以。

两个都没配就没有输入区,页面上会说明原因;Agent 不在时字幕里出现一句能读懂的话,而不是空转。

## 对话框按钮行:读数、附图、模型与真权限

输入框下面一行按钮(附图、用量读数、历史、模型、权限、发送),数据都从控制台来,页面仍只连
本 World 这一个来源:

| 能力 | 路径 |
|---|---|
| 上下文用量(条 + 计数;过软预警线变黄,满过预算变红) | World 轮询控制台 `/api/status`(页面连着才轮,2 秒一次,连上先取一次),压成 `status` 随 `/state` 帧下发 |
| 附图(选择/拖入/粘贴;8 张、长边 2048、单张 6MB,与控制台对话框同限) | 页面归一化成 base64,随 `{type:'msg', text, images}` 走 `/chat`——终端通道本来就收这个字段,代理不动 |
| 权限按钮(每次问/放行/关,三态弹层) | `GET/POST /dialog/config` → 控制台 `/api/config`,读写 `worlds.work.permission`——她请 DSH 干活的真权限,值在 work 扩展包的配置组里;work 组不在(扩展没装)时按钮收起 |
| 模型选择(先选端点实例,实例内再换模型名) | `GET /dialog/providers`(manifest 里 llm 页各取 `settings/state` 合成平表)、`GET /dialog/models?name=`、`POST /dialog/model` → 语言模型页的 `activate`。实例内换名保住模型档的其余键,只改 `model` |

没配 `consoleUrl` 时代理端点回 409,走控制台的那三样(用量/模型/权限)不出现;控制台不在时
端点给一句能读懂的话,状态轮询保上一次的值、只在失败沿报一次日志。

## 眼神跟随自己算,不用库自带的

`pixi-live2d-display` 的 `autoInteract` 关掉了。它把指针映射成从模型中心出发的**角度**,
目标点永远落在单位圆上(看哪儿都是满偏),再用速度上限约 0.6/秒的物理逼近,满量程要 1.6 秒
才到;它还会写 `ParamBodyAngleX = 10·x`,于是腰跟着鼠标转。

这里按**指针位置**给偏移(看着她的脸就是看正前方),用 0.03 秒的时间常数指数逼近(与帧率无关),
只叠加眼睛与一点头(`ParamEyeBallX/Y`、`ParamAngleX/Y`,名字从通道表来),身体参数一个都不写。
指针离开窗口就慢慢看回正前方。

## 台词就是演出指令

她说出「呜……不好意思」就该脸红,说出「唱一小段」就该切到唱歌。`expressions.json` 把这件事写成
数据:`{ expression, words[] }` 一张表,正文里出现 `words` 里的词就挂 `expression`。规则只有三条:

- **按表序取第一条命中的**——表的顺序就是优先级;
- **同一条指令在一段话里只触发一次**,长词先匹配(「不开心」不会被「开心」抢走);
- **模型上没有的表情名不进推流帧**,启动时按 model3 的表情表过滤并报出被丢掉的词。

匹配看的是她这一轮说过的正文(按整段攒,词被切在两个增量里也认得出来)。它压过心情那张表情,
`expressionHoldMs` 到期后回到心情。表情参数不走库的 `setExpression()`:它的队列永不结束,上一张
的开关会一直残留,所以页面每帧按帧里下发的清单与值自己写(见上一节的第 4 层)。

## 语音与口型

配了 `worlds.live2d.ttsUrl`(GPT-SoVITS api_v2,例如 `http://127.0.0.1:9880`),她的话自动
走语音:回复流按句界切段(`voiceSegmentMinChars` 攒短句、`voiceSegmentMaxChars` 封顶),
逐段经一条串行合成链进队列——上一段还在合成时,页面已经在播更早的段。参考音频四键
(`ttsRefAudioFile` / `ttsPromptText` / `ttsPromptLang` / `ttsTextLang`)随配置发给服务。

配了 `worlds.live2d.ttsTranslateUrl`(约定:`POST <地址>/translate`,JSON `{ text }` 回
`{ text }`),每段先翻成目标语言再进合成——字幕不受影响,始终显示原文;翻不出来就用原文
合成,不静音。这是"文字一种语言、声音另一种语言"的接法:api_v2 对钉死语言的文本会把
中日韩汉字一律按该语言念,跨语言出声必须先翻。

队列经 `/state` 帧交给页面:帧里带队首的取件地址(`voice: { id, url }`),页面取件、回执
(`/voice/heard`)、解码进本地待播队列**按序播放**,回执后队首出队,重连不重播。打断、
交出话语权与最后一页断连都会清队;帧里的清队代号(`voiceReset`)变了,页面就停掉在放的、
丢掉待播的。没有页面在看就不合成——没人看就没有"说出去"。`POST /voice/say`
JSON `{ text, lang? }` 是手动入口,同一条合成链、排在在途的段之后;没配 `ttsUrl` 或没有
页面连着时回 409。

页面播放走 Web Audio:解码后接 AnalyserNode,每帧取振幅(RMS)放大成口型开合,张嘴快、
合嘴稍慢(两个时间常数,与帧率无关)。浏览器要求用户点过页面才许出声:第一段语音会挂着
等一次点击,页面上有说明。

没语音在放时,口型回退到按字数估的振荡(`speechMsPerChar`,毫秒/字)——那是**估算,不是
唇形同步**;说出声的标志(`speaking`)在估的时长之内、或队列里还有段时为真。间隔超过
`speechGapMs`(默认 900ms)才算新的一句,所以分几轮说完的一段话不会每轮都重来一次起音。

## 按键发言

配了 `worlds.live2d.asrUrl`(约定:`POST <地址>/asr`,请求体是原始音频,回 JSON
`{ text }`),输入区多一枚「按住说」:按住开录(MediaRecorder),松开把音频整段
`POST /voice/hear`——World 原样转给转写服务,把文本带回来;页面拿文本走**与打字输入
同一条路**(控制台通道或外部 Agent),所以转写出来的话与她看到的打字输入没有分别。
牌子照实写此刻在干什么:在录、转写中;没听清给一句能读懂的话。没配 `asrUrl` 时
`/voice/hear` 回 409,按钮也不出现;浏览器没有录音 API 时同样收掉。

## 通道是抽象层

包说 `FaceAngleZ`,模型接的是 `ParamAngleZ`;`params.json` 的 `suggests` 是建议映射,
`range` 是裁剪边界,`losesIfMissing` 说明缺了这条通道会丢掉什么表演。换模型只换映射。

分辨率有优先级:**部署覆盖(`paramMap`) > 包的建议 > 模型自带的映射 > 不接**。模型自带的那份来自
它附带的 VTube Studio 配置(`ParameterSettings[].OutputLive2D`,作者写的),**只在建议落空时**才用
——那份配置是给人用的界面文件,会留笔误。

## 值也有约定差,不只是名字

`paramOffset` 补的是**值的约定**。实测这份模型:

| 通道 | 包说 | 模型参数说 | 照包写会怎样 |
|---|---|---|---|
| `EyeOpenLeft`/`EyeOpenRight` | `[-1,1]`,**0=平常睁眼** | `ParamEyeLOpen` 是 `[0,1]`,**1=睁眼** | 写 0 → **眼睛全闭** |

所以这两条通道要 `paramOffset: "EyeOpenLeft=1,EyeOpenRight=1"`。偏移加在合成之后、裁剪之前,
情绪把它压低时仍然是"眯一点"而不是"闭死"。同类错位在别的模型上还会出现,判据是:包的区间伸到
模型参数区间之外、而包把 0 当中性。

## 不归通道管的参数:定值

`paramOverrides` 每帧写一次,用在不由通道驱动的参数上。实测:模型的水印挂在 `Param137` 上,
默认值 0 时三个水印图层的透明度是 1,值 1 才把它们压到 0。作者的使用说明写着「水印按键默认打开,
需在设置表情中关闭」,对应的就是这条参数——`paramOverrides: "Param137=1"` 关掉它,**不动模型文件**
(说明书同时写着不可二传二改)。

## 参数写在哪一刻

写参数只有一个正确的时刻:模型的 `beforeModelUpdate`——参数刚被复位、还没更新的时候。
自己的 `requestAnimationFrame` 与模型更新没有固定先后,写早了当帧就被抹掉;平滑仍在自己的帧里推进,
只有赋值挪进了那个钩子。眨眼参数(模型 `Groups` 里的 `EyeBlink`)走**加法**:眨眼逻辑每帧算出
眼睛开合,通道值在它上面叠加。覆盖式写会等于关掉眨眼,那比没有表情更像一张假脸。

## 数据有缺口,读取要报出来

真实包里 `vocab.json` 提到的 `fx_*` 特效片段并不存在于 `clips.json`。`loadPack` 把这些名字
列在 `missingClipIds` 里,引擎遇到它们就是不触发——静默跳过会让"特效为什么不出现"变成谜。
措辞表同理:`expressions.json` 提到、模型上没有的表情名在启动时报出来,并且不进推流帧。
