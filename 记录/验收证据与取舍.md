**③ 权限矩阵**

**④ 题目硬要求:显式要求忘记立即生效**
架构冲突:参考设计里删除归梦,且常驻内容住在**系统前缀**里,而前缀平时只在会话建立/交接/清空时重建,
光删文件不够。解法是补一个机械口子 + 一个工具:

- `CoreApi.reloadSystemPrefix()`:把已有的重建机制开给 Persona(排在安全轮次边界)。
- `forget` 工具:当场删文件 + 请求重建;拒绝 `CONSTITUTION.md`。

## 3. Lv3 表现层

素材:`bots/miku/vtuber-pack`(`params.json` 14 个抽象通道 / `clips.json` pulse 20 + sustain 12 + gaze 5 /
`vocab.json` 中文词 → 片段 + aliases)。通道是抽象层,模型参数由 `suggests` 决定。

**两路驱动合成一路通道值**(题目硬要求 + 框架优势都在):

- **内部状态**(题目硬要求):六个情绪维度各自相对**自己的出厂基线**归一化 → 通道基线,一直在。
- **她说的话**:`outputTap` 收正文增量过词表触发片段;别名归一、长词优先、同类 state 互相替换。
- **模型自带的表情**:离散心情挂这款模型的八个表情里的四个(害羞→脸红、温柔→前倾、元气→唱歌、
  开心→比心)。查过参数表:表情只写 `Param125`/`Param130-137`,与通道层的
  `ParamAngle*`/`ParamMouth*`/`ParamEye*`/`ParamBrow*` **完全不相交**,所以三层同时生效、互不覆盖。
  水印与她的标记(葱、QQ人)不在表里——不碰。

渲染服务实测(真实 HTTP + SSE):

| 请求 | 结果 |
|---|---|
| `GET /` | 200,注入 `miku.model3.json` |
| `/app.js` · `/pack/params.json` | 200 · 200(1787 字节) |
| `/lib/js/{pixi,cubism4,live2dcubismcore}.min.js` | 200 · 200 · 200(460KB/120KB/207KB) |
| `/model/miku.model3.json` · `/model/miku.moc3` | 200 · 200(9.5 MB) |
| `/state` SSE | 12 个通道,`speaking=false`,`clients=1` |

内部状态在驱动身体的直接证据:推流里是非零且缓慢漂移的通道值
(`FaceAngleY: -9.337 → -9.355 → -9.378`,来自情绪基线叠加 sustain 片段的待机噪声)。

**通道与模型参数是两回事,要核对**
包里的 `suggests` 只是**建议**:它按常见命名写(`ParamAngleZ`),而这份模型 141 个参数里有
`Paramgulian` 这种拼音命名。分辨率有优先级:**部署覆盖 > 包的建议 > 模型自带的映射 > 不接**,
启动时拿模型自己的 `DisplayInfo`(cdi3)参数表核对。实测:

| 通道 | 包建议 | 结论 |
|---|---|---|
| FaceAngleX/Y/Z · MouthOpen · MouthSmile · EyeOpen* · EyeRight* · Brow* | ParamAngle* / ParamMouth* / ParamEye* / ParamBrow* | 模型里都有 |
| **CheekPuff** | `ParamCheekPuff` | 模型上没有;**已按模型自带映射改成 `Paramgulian`(鼓脸)** |
| EyeLeftX / EyeLeftY | 包自己说「与右眼共用,可不接」 | 不接(正确) |

模型自带的映射来自它附带的 VTube Studio 配置(`ParameterSettings[].OutputLive2D`,作者写的)。
只用它补建议落空的通道,不用它覆盖建议——那份配置是给人用的界面文件,会留笔误
(这份模型把 `BrowRightY` 映到 `ParamBrowLAngle`,而 `ParamBrowRY` 真实存在)。

**`OutputTap.externalizes` 的落实**:只在**真有页面看着**且这一轮确实说了字时为真。
没人在看就没有外部输出,让新输入抢占去处理它更划算;有页面在看时返回真,动作不会说到一半被掐掉。

**渲染端复用**:同一套 pixi + Cubism Core + cubism4 与同一个模型(配置指向即用),
页面只做三件事——按 `suggests` 把通道映到模型参数、把突变平滑成动作、说话时对口型。
有语音在放时口型跟**真实音频振幅**(AnalyserNode 取 RMS,张嘴快合嘴慢两个时间常数);
没语音时回退到按说话时长估的振荡——那是估算,不是唇形同步。

## 5. 冲突表:题目 vs 框架,怎么解的

| # | 冲突 | 解决 |
|---|---|---|
| 1 | 题目要「身体由内部状态驱动」,而 vtuber-pack 是**台词/词汇驱动**的 | 两层都留:情绪算出的基线一直在,词表片段叠上去。基线不参与淡出 |
| 2 | 题目要「显式要求忘记立即生效」,框架里删除归梦、且常驻内容在前缀里 | 补 `CoreApi.reloadSystemPrefix()` + `forget` 工具,当场删并请求重建;写明已发出的前缀收不回 |
| 3 | 框架的 fork 只能跑活动端点 | 接受:梦跑在主模型上。per-fork 端点留作可选扩展 |
| 4 | 本地模型的模板不含 `.Tools`,既不投递工具声明也不产出 `tool_calls` | 具名回退:provider 侧把文本围栏块翻成调用,Persona 侧把工具表与写法写进前缀。换支持原生工具的端点则不触发 |
| 5 | 框架的前缀为缓存复用而稳定,不随轮次重建 | 保留该设计;只有「必须立刻生效」这一处(忘记)才主动请求重建 |
| 6 | 情绪词表分析是启发式推断,与诚实认识论张力 | 做成**可关闭的具名回退**(`emotion.enabled`);关掉后状态冻结、前缀照装 |
| 7 | 情感/记忆状态要不要写进前缀 | 只有**离散心情**进前缀:连续值每轮都变会让前缀复用率下降,而换挡不频繁 |
| 8 | 工具表进前缀每轮都要付 | 只取描述第一句;前缀 6846 → 4764 字符 |
| 9 | `people/` 只许追加,而她习惯先写 `# 标题` 再写正文 | 改**抽取器**而不是让模型迁就:取第一条非空非标题的正文 |
| 10 | 改控制台前端要重建 Web 产物,而重建必须在没有 bot 活着时做 | 形象页由 World 自己起服务提供,不碰控制台产物 |

## 6. 怎么跑起来(官方路径,已实测)

```powershell
cd D:\二面\cortico
.\scratch\start-miku.ps1          # 起服务并等它就绪,打印两个地址
.\scratch\start-miku.ps1 -Stop    # 关掉
```

它走的是仓库自己的入口 `corepack pnpm start miku`(不是我沙箱里那套 plain-node 绕行),
并从 `my-agent/.env` 取密钥。起来后:

- 控制台 `http://127.0.0.1:18790/` —— 在终端页跟她说话
- 形象页 `http://127.0.0.1:18795/` —— 身体跟着她的话与状态动

两点要知道:

- 官方入口**默认暂停启动**(`CORTICO_START_PAUSED ?? '1'`,让操作者决定什么时候开始)。
  脚本把它设成 0,所以起来就是运行状态;直接用 `pnpm start miku` 的话要在控制台里点开始。
- 端口避开 7761-7860:那是这台机器给 Hyper-V/WSL 的保留段。
